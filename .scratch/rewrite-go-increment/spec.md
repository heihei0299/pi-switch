# pi-switch Go 重写增量 — 后端前端详细对接

Status: ready-for-agent

## Problem Statement

`feat/rewrite-go@2f113a1` 已交付 Go 重写基座（`gin + modernc/sqlite + embed.FS + translator` 复用、`two-stage build + bubbletea`，`a1c7c26→3e9c305` 8 项决策）与 `2f113a1` 前对话的 4 项增量修复（`SupplierCreditsPanel` percent guard、`handleFetchModels` 真实 `GET <baseUrl>/models` enrich stub、`handleGetCredits` 3 窗口 `rolling 20% / weekly 45% / monthly 70%`、`new-provider` 残留已清）。但后端-前端的端到端契约仍有 6 处未锁：① API 合约的机器可验证形式与 `responsesMode` 400 / `validate` `level/path/message` / `gateway publish` 写前写后差异的断言 ② `WebUI` 的 `SWR` 缓存与 `preview pending`/`mutate` 一致性 ③ 实时统计的 `5s/30s/5min` 轮询与窗口透传/失败保留 ④ 网关与供应商的 UI 交互（`GatewayPanel` 预编辑 vs 直接写盘、`exposedModels/modelMap` 同步、`userAgent` disguise 实时预览、`handleFetchModels` enrich 合并、`+Add` 预设与 `2 vs 3` 回归）⑤ `webui/dist` 的 `//go:embed dist` 非法 `all:../../webui/dist` 修正与 `index.html` 回退/`/assets` 缓存及 `buildInfo` 哈希校验 ⑥ `TUI` 的 `list.Model + 3-tab` `tea.Msg` 流与 `daemon` 的 `~/.pi-switch/*.pid|*.log + kill -0/tasklist + DialTimeout` 跨平台。多供应商 `multi_supplier` 的 `3 vs 2` 网关契约与 `failover` 热更新亦未以契约测试固化。需在不改代码的前提下，产出可直接 `tdd-implement` 的决策完备 Spec。

## Solution

在 `feat/rewrite-go@2f113a1` 基座上，以 **不破单文件 `config.json / requests.db`**、**保留 `gin TestMode + per-request 读取 + embed.FS //go:embed dist` 在 `webui` 包内** 为约束，锁 6 项增量契约：手写 `types.ts` 与 `gin json tag` 手动同步（辅契约断言，不引入 OpenAPI 生成）、`responsesMode` 400 仅校验不兼容组合、`validate` 仅 `GET /api/validate` 提示不阻塞 `PUT`、`gateway publish` 以写前空写后含 2 模型的 `providers[pi-switch]` 差异为回归；`SWR` 三键 `["profiles"] / ["gateway"] / ["stats", window]` + `mutate` 双键 + `debounce 300ms` 预览；轮询 `Off(默认)/5s/30s/5min`（`setInterval`，`modernc/sqlite` 无 `LISTEN` 不引入 `WebSocket`）+ 窗口透传与失败保旧 + 全量重算；`GatewayPanel` 的 `preview pending` 差分与 `merge_gateway_extra` 保留、`exposedModels` 主真源/`modelMap` 透传、`spoof` preset 与 `headers/Upstream` 合并、`handleFetchModels` 真实 `GET /models + Bearer` + 分字段 enrich、`+Add` 全选防 `2 vs 3`；`dist` 不入库 + 两阶段强制 + `fs.Sub(webUIFS,"dist")` 正解 + `no-cache vs immutable` 与 `SPA 200 vs /api 404` 分流 + `GET /api/buildInfo` 哈希；`bubbletea list.Model + 3-tab` 的 `tea.Msg` 流与 `FilterValue` 隔离 + `~/.pi-switch/*.pid|*.log` 的双探活与 `EADDRINUSE 500` 区分 + `conhost` 与 `pi-switch` 二进制名一致。全量契约均以最高缝（Go 二进制外部行为 + `httptest.Server` 上游 + `fs` + `~/.pi/agent/sessions`）可测。

## User Stories

1. As a pi 用户, I want to `GET /api/validate` 看到 `level/path/message` 的校验提示但 `PUT /api/profiles` 不被阻塞，so that 先保存再网关发布时校验
2. As a pi 用户, I want to `responsesMode=passthrough` 仅在 `api=openai-responses` 时 200 否则 400，`convert` 仅在 `api=openai-completions` 时 200，so that 不兼容组合被保存时阻止而非运行时降级
3. As a pi 用户, I want to `PUT /api/gateway/publish` 前看到 `Current vs Proposed` 的 `added/removed/changed` 差分（`pending_count`），so that 误改可预览后再落盘
4. As a pi 用户, I want to 网关发布前 `models.json:providers` 为 `{}` 或缺 `pi-switch`，发布后含 `pi-switch` 的 2 模型（`exposedModels` 过滤），so that `3 vs 2` 回归被契约捕获
5. As a pi 用户, I want to WebUI 的 `SWR ["profiles"]/["gateway"]/["stats", window]` 在 `PUT profiles|gateway/publish` 后自动 `mutate`，so that `ProfilesPanel` 的 `exposed` 选中态即时一致
6. As a pi 用户, I want to `ProfilesPanel` 的 `userAgent` 预设（`claude-code/codex/gemini/none`）改动 300ms 后预览 `headers` 的 `X-Custom` 合并，so that `disguise` 生效可观测
7. As a pi 用户, I want to Stats 页 `Auto-refresh Off/5s/30s/5min` 轮询 `GET /api/stats?window=...`，失败保留旧数据与旧窗口，so that 网络抖动不丢视图
8. As a pi 用户, I want to Stats 的 `byConversation/byModel` 每次轮询全量重算（`okRequests` vs `total`），`SupplierCreditsPanel` 的 `percent` 永不 `undefined`，so that 统计不漂移
9. As a pi 用户, I want to `Fetch from provider` 真实 `GET <baseUrl>/models`（`Bearer <apiKey>`）并 `enrich` 模型的 `cost/limit/reasoning`，`loading` 时禁点、`error` 时保留本地、`EnrichStats` 可见，so that 私有模型不报错且参数无需手填
10. As a pi 用户, I want to `+Add` 供应商时必选 `preset`，新建 `exposedModels` 默认全选（可逐项取消），so that `new-provider` 的 `3 vs 2` 残留不再出现
11. As a pi 用户, I want to `GET /` 返回 `no-cache` 的 `index.html`，`GET /assets/*` 返回 `immutable` 的哈希资源，`GET /api/unknown` 404 json 而 `GET /unknown-page` 200 html，so that SPA 与 API 错误可区分
12. As a pi 用户, I want to `GET /api/buildInfo` 返回 `version/buildTime + webui{embedded,indexHash,script,assetCount}` 供 hard refresh 校验，so that `npm run build:webui` 与 Go 二进制不同步时可提示
13. As a pi 用户, I want to `pi-switch tui` 以 `1:profiles 2:gateway 3:stats q:quit` 三 tab 完成 `enter` 切换、`g` 发布网关、`s/r` 刷新统计，`/` 过滤仅匹配 `name`，so that 无浏览器时可操作
14. As a pi 用户, I want to `pi-switch proxy/webui start --daemon --host --port` 以 `~/.pi-switch/*.pid|*.log` 常驻，`stop/status` 清 stale 并提示 `ss -tlnp` 多实例，`EADDRINUSE` 区分 500，so that 多实例与端口占用可诊断
15. As a pi 运维, I want to `webui/dist/*` 不入库且 `//go:embed dist` 仅在 `webui/embed.go`，`internal/server` 仅 `fs.Sub(webUIFS,"dist")`，so that `go vet` 与 `grep -r "go:embed.*\.\."` 回归保护

## Implementation Decisions

- **API 合约与校验（01）**：手写 `webui/src/types.ts` 与 `internal/server` 的 `json` tag 手动同步，不引入 `OpenAPI + openapi-typescript/oapi-codegen`；辅以 `go test` 的契约断言（`gateway publish` 写前写后差异见 4）。`400` 仅用于 `responsesMode` 不兼容（`passthrough` 仅允许 `openai-responses`，`convert` 仅允许 `openai-completions`，`validateProfileResponsesMode` 在 `POST /profiles` 与 `PUT /profiles/:name` 及 `PUT /config` 的原始 json 预检均 `400 {"error":...}`），其余 `404 for unknown profile / 500 for upstream` 分散。`validate_config` 的 `ValidationIssue{level,path,message}` 仅由 `GET /api/validate | GET /api/config/validate` 返回提示（`warning` 含 `no models / modelsDevProvider unknown / failover not found`），不作为 `PUT` 前置阻塞，允许先保存再 `gateway publish` 时校验。

- **网关发布契约（01+04 联动）**：`PUT /api/gateway/publish`（兼容 `PUT /api/models/gateway`）的契约测试断言写前 `models.json:providers == {} || missing pi-switch`，写后 `providers[pi-switch]` 含 `exposedModels` 过滤后的 2 模型（`id="{supplier}/{modelId}"`，`reasoning` 补 `compat.supportsDeveloperRole=false`），`preview pending` 的 `diffGateway(current,proposed)` 的 `added/removed/changed` 亦纳入断言（`pending_count = added+removed+changed`），回归 `multi_supplier` 的 `3 vs 2`。

- **WebUI 状态同步（02）**：数据抓取选 `SWR`（不选 `React Query`），缓存键 `["profiles"] / ["gateway"] / ["stats", window]`；`mutate` 时点为 `PUT /api/profiles|gateway/publish|/proxy/failover` 后 `mutate ["profiles"]` 与 `["gateway"]` 双键（`GatewayPanel` 的 `load()` + `refresh()` 封装），窗口维度 `today|24h|7d|custom` 的 `from/to` 透传。乐观更新取 **等待确认**（`PUT` 后等待 `GET /api/profiles` 成功再更新本地列表），避免与 `gateway publish` 的 `exposedModels` 竞争。`userAgent` disguise 的实时预览为 `debounce 300ms` 后 `modelPreview(draft)` 合成 `preview headers` 的 `X-Custom` 合并，`Upstream` 聚合时可见，不自动写盘。

- **实时统计（03）**：推送选 **轮询** `GET /api/stats?range=&from=&to=&page=&limit=` 的 `Off(默认)/5s/30s/5min` 四档（`setInterval`），`modernc/sqlite` 无 `LISTEN/NOTIFY` 不引入 `WebSocket/SSE` 的 `gin handleStatsStream`。窗口参数在轮询间透传 `today|24h|7d|custom` 的 `from/to`（`parseWindowQuery` 四档），`auto-refresh` 失败保留旧数据与旧窗口。`handleGetCredits` 的 `SupplierCreditsPanel` 3 窗口为 `rolling 20% / weekly 45% / monthly 70%`，`percent` 为已用/总量，`percent` `undefined` 时 `guard` 为 `0`（`handoff 2f113a1` 已修）。聚合口径每次轮询 **全量重算** `byConversation/byModel`（`okRequests` vs `total`，`recentRequests` 分页 `page/limit`），避免增量漂移；`totalCost` 仅对 `success=1 && prompt+completion 可解析` 行累加，`costUnknown` 计 `success=1` 但 `cost==nil` 行。

## Testing Decisions

- **好的测试**：只测外部行为——给定 CLI 输入/HTTP 请求/文件系统状态（含 `~/.pi-switch/*` 与 `~/.pi/agent/sessions`），断言 CLI 退出码与输出、HTTP 响应（含流式事件与 `Cache-Control`）、`config.json/models.json/requests.db/requests.log` 落盘与 `api/buildInfo` 哈希；不测 `internal/*` 内部函数与私有状态。
- **缝（Seam）**：单一最高缝——Go 二进制的外部行为（CLI + `127.0.0.1:43112` 代理 + `127.0.0.1:43110` 管理/WebUI 的 `embed.FS` + 文件系统 `~/.pi-switch/*` + `~/.pi/agent/sessions`）。6 项增量契约均在该缝可观测，符合“最少缝、最高缝”原则。
- **API 合约与网关**（先例：`cargo test --lib` 的 `config` 校验、`proxy` 限流）：`httptest.Server` mock 上游的 `GET /v1/models`（`Bearer`）、`responsesMode` 400（`passthrough↔openai-responses/convert↔openai-completions`）、`validate` 的 `level/path/message` 与 `modelsDevProvider/failover` warning、`gateway preview` 的 `pending_count` 与 `merge_gateway_extra` 保留、`publish` 写前空写后含 2 模型的 `models.json` 差异（含 `slot` 时序）。
