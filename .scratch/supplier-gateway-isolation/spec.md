# 供应商与网关彻底独立（显式发布）

Status: ready-for-agent

## Problem Statement
供应商管理与网关发布仍存在隐式耦合：个性伪装、设置变更与代理启动会自动写网关文件，导致“改供应商即改网关”的不可预期副作用、发布不可审计、错误互相穿透。用户需要两者彻底逻辑独立——除显式发布外，任何供应商或设置变更都不触网关，启动亦不自动同步。

## Solution
确立供应商为唯一事实来源，网关为只读派生视图；移除剩余自动写网关路径，统一收口到显式网关发布，启动改为健康检查与不一致提示；两者在存储、逻辑与运行时双向错误隔离，为未来独立进程预留接口但本次不真拆进程。

## User Stories
1. As an 供应商管理员, I want to 新建/更新/删除供应商后网关不自动变更, so that 发布可控可审计
2. As an 供应商管理员, I want to 修改供应商已暴露模型集合后仅产生待发布差异, so that 可在网关面板确认后再发布
3. As an 供应商管理员, I want to 修改供应商个性伪装后不自动写网关, so that 伪装变更不意外影响网关
4. As an 管理员, I want to 修改网关全局设置（gatewayApi/host/port/providerPrefix）后仅标记待发布而不落盘, so that 设置变更同样走显式发布
5. As an 管理员, I want to 切换/复制供应商后网关不自动同步, so that 切换操作可批量后再统一发布
6. As an 管理员, I want to 在网关面板看到 Current vs Proposed 差异、待发布数与冲突提示, so that 明确待发布内容
7. As an 管理员, I want to 通过网关面板“应用到 Pi”显式发布且失败时不丢失编辑态, so that 发布可重试可回滚
8. As an 管理员, I want to 代理启动时不自动写网关而是以健康检查与首屏不一致横幅提示, so that 启动不产生隐式写
9. As an 管理员, I want to 网关预览/发布失败时供应商 CRUD 仍可用, so that 两侧故障隔离
10. As an 管理员, I want to 供应商校验/落盘失败时网关读/预览/健康仍可用, so that 反向亦隔离
11. As an 供应商管理员, I want to 以多上游形态编辑供应商（单字段兼容回退）而网关仍按主上游聚合, so that 兼容存量且不扩大契约
12. As an 管理员, I want to 通过独立健康检查获知网关是否就绪、是否有模型文件、待发布上游总数, so that 可观测
13. As an 管理员, I want to 存量未知字段在网关合并时透传保留但不成为权威, so that 兼容不提权
14. As an WebUI 用户, I want to 在 Profiles 相关面板保存时仅提示“已保存到本地，需到网关发布”而不弹网关预览, so that 心智模型一致
15. As an WebUI 用户, I want to 在网关离线时仍能正常增删改供应商, so that 前端亦隔离

## Implementation Decisions
- 模块职责收口：供应商侧仅操作供应商存储与设置，网关侧仅操作网关存储与健康；网关文件的唯一写入口为显式发布，其余供应商与设置接口移除自动写路径
- 发布语义统一：所有供应商与设置变更标记为待发布，预览为干跑不写盘，发布为原子写并通知；启动路径由同步改为健康检查与不一致提示
- 聚合口径不变：上游归属供应商，多上游通过回退兼容单字段，网关当前仍按主上游聚合生成合成视图，未扇出多条目
- 兼容策略不变：空上游列表不落盘，未知字段透传仅保留不提权；不做批量迁移
- 路由与错误隔离：供应商与网关分属独立路由组与错误转换，任一侧 400/500 不串扰另一侧；前端面板错误边界隔离，网关离线不阻断供应商渲染与操作
- 预留而非真拆：为独立网关进程预留健康检查、启动占位与文件通知接口，明确后续真拆路径但本次保持同进程逻辑隔离

## Testing Decisions
- 好测试只验外部行为：供应商路由写后网关预览的 pending 是否如期变化、发布后网关文件是否如期落盘、错侧失败是否不穿透；不测实现细节的内部调用计数
- 测试 seam：以 Web API 集成为主 seam（供应商写不自动落盘、显式发布才落盘、双侧错误隔离、健康检查），辅以网关模块单元（预览/发布/校验/健康）与供应商侧单元（CRUD/设置回退）、WebUI 组件单测（保存不触发网关预览、发布按钮与状态条）
- 先例复用：沿用既有网关预览/发布与路由独立性测试形态，以及 WebUI 上游回退与网关健康单测形态

## Out of Scope
- 不真拆为双进程/双二进制，不引入 IPC 替代文件通知
- 不改变模型派生与富化规则，不扇出多上游为多条网关条目
- 不引入文件建议锁升级，不接管非网关 provider 的独立编辑权威
- 不改变代理转发仅读供应商的运行时路径
